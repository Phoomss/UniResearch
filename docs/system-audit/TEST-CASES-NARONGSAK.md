# Test Cases ของ Narongsak

ชื่องานปัจจุบันใช้ชื่อเต็มจาก [migrate.py/seed_thai_data.py](TEST-RESEARCH-DATA.md) พร้อมระบุสำเนาที่เตรียมเพิ่ม สถานะและการเชื่อมบัญชี CSV เป็นเงื่อนไขบนฐานทดสอบ ไม่ใช่ผล migration หรือผลทดสอบย้อนหลังของบุคคลนั้น

ฉบับข้อมูลทดสอบปัจจุบันใช้ชื่อ/อีเมลจาก [student.csv](../../backend/app/scripts/student.csv) และ [advisors.csv](../../backend/app/scripts/advisors.csv) ตามตารางใน [Test Cases ข้อ 1.2](TEST-CASES.md#12-สภาพแวดล้อมและข้อมูลร่วม) ต้องเตรียมสำเนาฐานทดสอบให้ตรงก่อนรัน เลขผู้ใช้ในเอกสารเป็น mapping ของฐานทดสอบตามแผน ไม่ใช่ id จาก CSV ผลย้อนหลังอ้างข้อมูลของรอบเดิม ส่วนผลรันด้วยบัญชี CSV และ migration ปัจจุบันแยกใน [รายงานปรับสคริปต์ 16 ตุลาคม](SELENIUM-CSV-MIGRATION-ALIGNMENT-2026-10-16.md)

ระบบ UniResearch มีกรณีทดสอบที่มอบหมายให้ Narongsak ทั้งหมด **18 กรณี** โดยชื่อผู้ทดสอบหมายถึงการจัดสรรตามแผน ผลรันอัตโนมัติที่อ้างอิงดำเนินการโดย Codex

ชื่อกรณีด้านล่างใช้ชื่อฉบับทบทวนและอีเมลจาก CSV จริงในฉบับข้อมูลทดสอบปัจจุบัน ส่วนผล PASS ย้อนหลังอ้าง assertions ของสคริปต์ ณ session นั้น ไม่ใช่การยืนยันเงื่อนไขที่เพิ่มภายหลัง

## ผลการทดสอบ

ฉบับทบทวนเนื้อหา 16 ตุลาคม 2026: ตารางด้านบนอ้างผล **18 PASS ใน session เดียว** `20261014-102745-778362` บน Chrome headed 155.0.8059.41 / SQLite / provider mock, commit `7ff6c6750f0982ca4a34834daf5dee5ff223e976` พร้อม working tree ดู [UI report](../../tests/selenium/reports/20261014-102745-778362/UI-TEST-EXECUTION.md) และ [JSON](../../tests/selenium/reports/20261014-102745-778362/ui-results.json)

Session focused ก่อนปรับสคริปต์ `20261016-094537-437659` เลือกเฉพาะ **TC-038 PASS / อีก 17 NOT RUN** ไม่ใช่ผลผ่าน 18/18 ของวันที่ 16 ตุลาคม ดู [ผล U16](../../tests/selenium/reports/20261016-094537-437659/UI-TEST-EXECUTION.md) ผล U14 ไม่ถูกยกมาเป็น PASS ของ U16

ทั้ง 18 กรณีปัจจุบันมี UI รวม TC-013 และทั้งสี่ tabs ใน TC-046 โดยมี API/DB assertions เสริม รายงาน Brave วันที่ 8 ตุลาคมที่จัดสองกรณีนี้เป็น API-only เป็นขอบเขตของสคริปต์รุ่นเดิม

Test Cases ฉบับทบทวนเพิ่มเงื่อนไขตรวจหลายข้อ การรับรองเงื่อนไขใหม่ทั้ง UI/ส่วนเสริมยังรอทวนส่วนที่สคริปต์ไม่ได้ assert ไม่ใช้ PASS ของ U14 รับรองสิ่งที่ไม่ได้ assert ในรอบนั้น ผล execute หลังปรับ fixture ดู [รายงานปรับสคริปต์](SELENIUM-CSV-MIGRATION-ALIGNMENT-2026-10-16.md) โดยไม่ยกผล U14 มารวม

### ผลย้อนหลังวันที่ 8 ตุลาคม

ผลรันอัตโนมัติหลังแก้แจ้งเตือนวันที่ **8 ตุลาคม 2026: ผ่าน 18 / ไม่ผ่าน 0 / ไม่ได้เลือก 30** ใช้เวลา 161.10 วินาที ดู [หลักฐานรันทั้ง 18 กรณี](../../tests/selenium/artifacts/20261008-042008-398982/report.md)

ผลก่อนแก้คือ **ผ่าน 17 / ไม่ผ่าน 1** โดย **TC-043** ไม่ผ่าน เพราะ browser client ส่งคำขอไปผิด URL จึงไม่แสดงแจ้งเตือนใน dropdown การแก้ให้ใช้ Next.js proxy พร้อม session ทำให้กรณีนี้ผ่าน รวมทั้งการกดอ่านทีละรายการและอ่านทั้งหมดผ่านหน้าเว็บ โดยแจ้งเตือนของผู้ใช้อื่นไม่ถูกเปลี่ยน

การรันนี้ใช้ฐานข้อมูล SQLite ชั่วคราวและ AI test double จึงยังไม่ยืนยันพฤติกรรม PostgreSQL/pgvector หรือคุณภาพของ AI provider จริง
