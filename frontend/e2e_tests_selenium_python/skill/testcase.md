## 2. กฎเหล็ก 5 ข้อที่ต้องปฏิบัติตามอย่างเคร่งครัด (Mandatory Rules)

### กฎข้อที่ 1: ระบบรหัส Test Case ใหม่ และการอ้างอิงกลับไปยังโปรเจกต์หลัก

   - `Master TC-003 | FR-002` (การเข้าสู่ระบบและจัดการเซสชัน)
   - `Master TC-005 | FR-003` (การดู/แก้ไขโปรไฟล์และเปลี่ยนรหัสผ่าน)
   - `Master TC-017 | FR-010` (การแสดงผลสถิติ งานวิจัยล่าสุด และยอดนิยม)
   - `Master TC-023 | FR-014` (การควบคุมสิทธิ์การเข้าถึงหน้าส่งผลงานวิจัย)
   - `Master TC-026 | FR-016` (การอัปโหลดไฟล์ชนิดถูกต้องและการทดสอบขนาดขอบเขต)
   - `Master TC-027 | FR-016` (การตรวจสอบนามสกุล MIME และลายเซ็นไฟล์)
   - `Master TC-035 | FR-021` (การควบคุมสิทธิ์ดาวน์โหลดและกรณีไม่มีไฟล์แนบ)
   - `Master TC-042 | FR-027` (การบันทึกและยกเลิกรายการผลงานวิจัยที่สนใจ)

### กฎข้อที่ 2: การแยกกรณีทดสอบแบบละเอียด (Atomic & Granular Test Cases)
1. ห้ามมัดรวมหลายเงื่อนไขไว้ใน Test Case เดียว (1 Test Case = 1 เงื่อนไขการทดสอบที่ชัดเจน)
2. ต้องแยกกรณี Positive, Negative, Boundary (ขนาดปกติ vs ขนาดพอดีขีดจำกัด vs ขนาดเกินขีดจำกัด), ประเภทไฟล์ (PDF เอกสาร vs ภาพหน้าปก), และระดับสิทธิ์ผู้ใช้งาน (Unauthenticated Visitor vs Guest vs Student) ออกเป็นเคสเดี่ยวๆ ครบ 26 เคส

### กฎข้อที่ 4: ขั้นตอนการทดสอบ (Test Steps) ต้องอธิบายละเอียดตั้งแต่ต้นจนจบ
1. เขียนเรียงลำดับเป็นข้อๆ (`1.`, `2.`, `3.`, ...) อธิบายตั้งแต่การเปิดเว็บเบราว์เซอร์ เข้าสู่ URL ใด
2. ระบุชัดเจนว่าผู้ใช้งานมองเห็นหน้าจออะไร คลิกที่เมนูหรือปุ่มชื่ออะไร (ทั้งภาษาไทยและอังกฤษตาม UI จริง)
3. ระบุว่ากรอกข้อมูลอะไรลงในช่องไหน ด้วยค่าข้อมูลใด และกดปุ่มใดเพื่อส่งข้อมูล

### กฎข้อที่ 5: ผลลัพธ์ที่คาดหวัง (Expected Result) และผลการทดสอบจริง (Actual Result) ต้องเห็นภาพเหมือนผู้ใช้งานจริง
1. **ห้ามเขียนสั้นๆ** แค่ `"ได้ HTTP 200"` หรือ `"สำเร็จ"`
2. **ผลลัพธ์ที่คาดหวัง (Expected Result):** อธิบายสิ่งที่ปรากฏบนหน้าจอ (เช่น ระบบเปลี่ยนหน้าไปยัง URL ใด, แสดง Toast แจ้งเตือนสีเขียว/แดงข้อความว่าอย่างไร, ปุ่มเปลี่ยนข้อความ/สถานะอย่างไร, ฟอร์มแสดงข้อมูลอะไร) ควบคู่กับสถานะของระบบหลังบ้านและฐานข้อมูล
3. **ผลการทดสอบจริง (Actual Result):** บันทึกสิ่งที่เกิดขึ้นจริงจากการรัน Selenium E2E อธิบายผลบน UI ตรงตามมุมมองผู้ใช้งาน พร้อมระบุเวลาที่ใช้ประมวลผลจริง (เช่น `ใช้เวลา 2.15 วินาที`)

3. **ตารางรายละเอียดกรณีทดสอบรายเคส (Detailed Test Case Tables — ครบทั้ง 26 เคส):**

   - **ผลลัพธ์ที่คาดหวัง (Expected Result):** อธิบายสิ่งที่ปรากฏบนจอภาพ (Toast, URL, ข้อมูลบนการ์ด) ควบคู่กับสถานะระบบหลังบ้าน

   - **สถานะการทดสอบ (Status):** `☑ ผ่าน (PASS)  ☐ ไม่ผ่าน (FAIL)`
