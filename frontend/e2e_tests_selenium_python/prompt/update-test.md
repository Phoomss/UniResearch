# MASTER TASK PROMPT: ยกเครื่องชุดทดสอบ E2E Selenium Python และสร้างเอกสาร Test Plan / Test Case ฉบับสมบูรณ์

## 1. ภาพรวมภารกิจ (Mission Overview)
คุณได้รับมอบหมายให้ปรับปรุงและขยายผลระบบทดสอบอัตโนมัติ E2E (Selenium + Python + pytest) ในโฟลเดอร์ `D:\UniResearch\frontend\e2e_tests_selenium_python` รวมถึงสคริปต์สร้างเอกสาร `docs/testplan.docx` และ `docs/testcase.docx` และชุดคำสั่งใน `skill/` ของโปรเจกต์ `D:\UniResearch` ให้สมบูรณ์แบบที่สุด

ปัญหาของชุดทดสอบและเอกสารชุดเดิม (ที่มีเพียง 8 เคสหลัก ได้แก่ `TC-003`, `TC-005`, `TC-017`, `TC-023`, `TC-026`, `TC-027`, `TC-035`, `TC-042`) มี 5 ประเด็นหลักที่ต้องแก้ไขให้ครบถ้วน:
1. **การจัดรหัส Test Case ใหม่และการอ้างอิง:** เดิมใช้รหัสข้ามเลขตามเอกสารรวมของโปรเจกต์ (`TEST-CASES.md`) และมัดรวมหลายการทดสอบไว้ในรหัสเดียว ให้ทำการ **แตกกรณีทดสอบย่อยและรันรหัสใหม่เรียงกันตั้งแต่ `TC-001` ถึง `TC-026`** พร้อมใส่ฟิลด์อ้างอิงกลับไปยังรหัส Test Case หลักของโปรเจกต์ (`Master TC-XXX`) และ `FR-XXX`
2. **การแตกแขนง Test Case ให้ละเอียดที่สุด (Granular Breakdown):** แยกแต่ละกรณีทดสอบออกจากกันอย่างชัดเจน (1 Test Case = 1 เงื่อนไขการทดสอบ) ไม่นำ Positive, Negative, Boundary, รูปภาพปก, เอกสาร PDF หรือสิทธิ์ผู้ใช้คนละแบบมารวมในเคสเดียวกัน
3. **ข้อมูลเงื่อนไขและข้อมูลทดสอบต้องเสมือนผู้ใช้งานจริง (Real User Personas):** ห้ามเขียนข้อมูลทดสอบเป็นตัวย่อ เช่น `S1`, `U1`, `G1` หรือ `"ชื่อ-นามสกุลใหม่"` ลอยๆ ต้องใช้ชื่อ-นามสกุลคนจริง อีเมลจริง รหัสนักศึกษา ภาควิชา ชื่อผลงานวิจัย และชื่อไฟล์ที่มีความหมายเหมือนผู้ใช้งานจริง
4. **ขั้นตอนการทดสอบ (Test Steps) ต้องละเอียดและเข้าใจง่าย:** อธิบายตั้งแต่การเปิดเว็บเบราว์เซอร์ เข้าสู่ URL ใด คลิกปุ่มชื่ออะไร กรอกข้อความอะไรลงในช่องไหน จนจบขั้นตอน เพื่อให้คนทั่วไปหรือผู้ใช้งานจริงอ่านตามแล้วเข้าใจทันที
5. **ผลลัพธ์ที่คาดหวัง (Expected Result) และผลลัพธ์จริง (Actual Result) ต้องเห็นภาพเหมือนใช้งานจริง:** อธิบายทั้งสิ่งที่ผู้ใช้งานมองเห็นบนหน้าจอ (หน้าเว็บเปลี่ยนไปหน้าไหน, แสดงข้อความแจ้งเตือน Toast ว่าอย่างไร, ปุ่มหรือการ์ดแสดงผลอย่างไร) ควบคู่กับสถานะการทำงานจริงของระบบ

## 2. ขั้นตอนการดำเนินงาน (Step-by-Step Execution Plan)

### STEP 1: สำรวจและวิเคราะห์โครงสร้างเดิมทั้งหมด
ให้อ่านและวิเคราะห์ไฟล์ต่อไปนี้ก่อนเริ่มลงมือแก้ไข:
1. โครงสร้างและโค้ดใน `D:\UniResearch\frontend\e2e_tests_selenium_python` ทั้งหมด (`tests/`, `pages/`, `conftest.py`, สคริปต์สร้าง `.docx`, `docs/`, `skill/`)
2. เอกสารของโปรเจกต์หลัก (เช่น `TEST-CASES.md`, `FUNCTIONAL-REQUIREMENTS.md`) และโค้ด Frontend (`D:\UniResearch\frontend`) / Backend (`D:\UniResearch\backend`) เพื่อตรวจสอบ URL, ข้อความแจ้งเตือนบน UI (Toast / Error Messages), ขีดจำกัดขนาดไฟล์ (`MAX_DOCUMENT_BYTES = 25 MB`, `MAX_COVER_IMAGE_BYTES = 5 MB`) และเงื่อนไข Validation จริงของระบบ

### STEP 2: อัปเดตไฟล์ Skill ใน `D:\UniResearch\frontend\e2e_tests_selenium_python\skill`
ให้อัปเดตหรือสร้างไฟล์ Skill ในโฟลเดอร์ `D:\UniResearch\frontend\e2e_tests_selenium_python\skill` จำนวน 2 ไฟล์ เพื่อเป็นแม่แบบมาตรฐานในการสร้างเอกสาร:
1. **Skill สำหรับสร้าง `testcase.docx`** (กำหนดโครงสร้างตารางสรุปและตารางรายละเอียดรายเคส `TC-001` ถึง `TC-026`, ช่องอ้างอิง `Master TC` และ `FR`, กฎการใช้ชื่อ-นามสกุลและอีเมลคนจริง, กฎการเขียนขั้นตอนตั้งแต่เปิดเว็บจนจบ, และกฎการเขียน Expected/Actual Result มุมมองผู้ใช้งานจริง)
2. **Skill สำหรับสร้าง `testplan.docx`** (กำหนดโครงสร้างแผนการทดสอบ, ตาราง Traceability Matrix จับคู่ `TC-001..TC-026` กับ `Master TC` และ `FR`, กลยุทธ์การทดสอบ Positive/Negative/Boundary/RBAC, ตารางข้อมูลผู้ใช้งานจริงและไฟล์ทดสอบ)

### STEP 3: แตกแขนง Test Case ออกเป็น 26 กรณีทดสอบย่อย (`TC-001` ถึง `TC-026`)
ให้ใช้โครงสร้างการแตกเคสทั้ง 26 กรณีทดสอบย่อยต่อไปนี้เป็นมาตรฐานเดียวกันทั้งใน **โค้ดทดสอบ Selenium (`tests/`)**, **เอกสาร `docs/testcase.docx`** และ **เอกสาร `docs/testplan.docx`**:

#### กลุ่มที่ 1: การเข้าสู่ระบบและจัดการเซสชัน (อ้างอิง `Master TC-003` | `FR-002`)
- **TC-001 (Ref: Master TC-003 | FR-002):** การเข้าสู่ระบบสำเร็จด้วยบัญชีนักศึกษาที่มีสถานะปกติผ่านหน้าเว็บไซต์ (`/login`)
  - *รายละเอียด:* เปิดหน้า `/login` กรอกอีเมลและรหัสผ่านของนักศึกษา (นายธนภัทร สุวรรณโชติ) กดปุ่ม `"เข้าสู่ระบบ"` ระบบเปลี่ยนเส้นทางไปยังหน้า `/account/saved` และแสดงข้อมูลผู้ใช้งานที่ล็อกอินสำเร็จ
- **TC-002 (Ref: Master TC-003 | FR-002):** การคงสถานะเข้าสู่ระบบและตรวจสอบข้อมูลผู้ใช้งานปัจจุบันหลังล็อกอินสำเร็จ (`/account/saved` & Session Verification)
  - *รายละเอียด:* หลังจากล็อกอินสำเร็จ ตรวจสอบการเก็บคุกกี้เซสชัน การรีเฟรชหน้าเว็บ `/account/saved` และการตรวจสอบข้อมูลบัญชีผ่าน `/api/auth/me` ว่าระบบยังคงสถานะล็อกอินของนายธนภัทร สุวรรณโชติ พร้อมสิทธิ์ `student` อย่างถูกต้อง

#### กลุ่มที่ 2: การดูโปรไฟล์ แก้ไขข้อมูลส่วนตัว และเปลี่ยนรหัสผ่าน (อ้างอิง `Master TC-005` | `FR-003`)
- **TC-003 (Ref: Master TC-005 | FR-003):** การเปิดดูข้อมูลส่วนตัวปัจจุบันในหน้าโปรไฟล์นักศึกษา (`/student/profile`)
  - *รายละเอียด:* ล็อกอินด้วยบัญชีนักศึกษา นำทางไปยังหน้า `/student/profile` ตรวจสอบว่าช่องข้อมูลบนหน้าจอแสดงชื่อจริง นามสกุล อีเมล รหัสนักศึกษา และภาควิชาปัจจุบันของนายธนภัทร สุวรรณโชติ ครบถ้วนถูกต้อง
- **TC-004 (Ref: Master TC-005 | FR-003):** การแก้ไขชื่อ-นามสกุลและเปลี่ยนภาควิชาในหน้าโปรไฟล์นักศึกษา (`/student/profile`)
  - *รายละเอียด:* ในหน้า `/student/profile` แก้ไขชื่อ-นามสกุล (เช่น จาก `"ธนภัทร สุวรรณโชติ"` เป็น `"ธนภัทร สุวรรณโชติกุล"`) และเลือกเปลี่ยนภาควิชาใหม่ กดปุ่มบันทึกข้อมูล ตรวจสอบข้อความแจ้งเตือน `"อัปเดตข้อมูลส่วนตัวสำเร็จ"` และรีเฟรชหน้าเว็บเพื่อยืนยันว่าข้อมูลที่แก้ไขถูกบันทึกอยู่จริง
- **TC-005 (Ref: Master TC-005 | FR-003):** การเปลี่ยนรหัสผ่านใหม่ในหน้าโปรไฟล์นักศึกษา และการเข้าสู่ระบบด้วยรหัสผ่านใหม่
  - *รายละเอียด:* ในหน้า `/student/profile` กรอกรหัสผ่านใหม่และยืนยันรหัสผ่านใหม่ กดปุ่มบันทึกข้อมูล ตรวจสอบแจ้งเตือนสำเร็จ จากนั้นออกจากระบบแล้วทดสอบเข้าสู่ระบบที่หน้า `/login` ด้วยรหัสผ่านใหม่ ระบบต้องอนุญาตให้เข้าสู่ระบบได้สำเร็จ (หมายเหตุ: ในโค้ดทดสอบให้คืนค่ารหัสผ่านกลับเป็นค่าเริ่มต้นหลังจบเคสเพื่อให้รันซ้ำได้เสมอ)

#### กลุ่มที่ 3: การแสดงผลหน้าแรก สถิติ ผลงานล่าสุด และผลงานยอดนิยม (อ้างอิง `Master TC-017` | `FR-010`)
- **TC-006 (Ref: Master TC-017 | FR-010):** การแสดงผลตัวเลขสถิติภาพรวมคลังงานวิจัยทั้ง 4 ด้านบนหน้าแรกของเว็บไซต์ (`/`)
  - *รายละเอียด:* เปิดหน้าแรก (`http://localhost:3000/`) เลื่อนไปยังส่วนสถิติคลังงานวิจัย (Discovery Stats Grid) ตรวจสอบการแสดงผลตัวเลขสถิติทั้ง 4 ด้าน (จำนวนผลงานวิจัย, จำนวนนักวิจัย, จำนวนหมวดหมู่, ยอดดาวน์โหลดสะสม) ว่าแสดงตัวเลขครบถ้วนและตรงกับข้อมูลในระบบ
- **TC-007 (Ref: Master TC-017 | FR-010):** การแสดงผลรายการผลงานวิจัยมาใหม่ล่าสุด (Latest Research) บนหน้าแรก (`/`)
  - *รายละเอียด:* บนหน้าแรก (`/`) เลื่อนไปยังส่วนแสดงผลงานวิจัยล่าสุด (Latest Research) ตรวจสอบว่าระบบแสดงการ์ดผลงานวิจัยที่ได้รับการอนุมัติแล้ว (`approved`) พร้อมชื่อเรื่อง ชื่อผู้วิจัย หมวดหมู่ และวันที่เผยแพร่อย่างถูกต้อง
- **TC-008 (Ref: Master TC-017 | FR-010):** การแสดงผลผลงานวิจัยยอดนิยม (Popular / Featured Research) บนหน้าแรก (`/`)
  - *รายละเอียด:* บนหน้าแรก (`/`) เลื่อนไปยังส่วนแสดงผลงานวิจัยยอดนิยม (Featured / Popular Research) ตรวจสอบว่าระบบแสดงการ์ดผลงานวิจัยที่ได้รับความนิยมสูงสุด (เรียงตาม `view_count`) พร้อมแสดงหัวข้อและรายละเอียดครบถ้วน

#### กลุ่มที่ 4: การควบคุมสิทธิ์การเข้าถึงหน้าส่งผลงานวิจัย (อ้างอิง `Master TC-023` | `FR-014`)
- **TC-009 (Ref: Master TC-023 | FR-014):** การป้องกันผู้ใช้งานที่ยังไม่ได้เข้าสู่ระบบ (Unauthenticated Visitor) ไม่ให้เปิดหน้าแบบฟอร์มส่งผลงานวิจัย (`/student/research/new`)
  - *รายละเอียด:* เปิดเบราว์เซอร์โดยไม่มีการล็อกอิน (ล้างคุกกี้/เซสชัน) แล้วพิมพ์ URL ไปที่ `http://localhost:3000/student/research/new` ระบบต้องบล็อกการเข้าถึงและเปลี่ยนเส้นทาง (Redirect) ไปยังหน้าเข้าสู่ระบบ (`/login?next=%2Fstudent%2Fresearch%2Fnew`) ทันที
- **TC-010 (Ref: Master TC-023 | FR-014):** การป้องกันการส่งข้อมูลสร้างผลงานวิจัยผ่าน API โดยไม่มีการยืนยันตัวตน (Unauthenticated API -> HTTP 401)
  - *รายละเอียด:* ทดสอบส่งคำขอสร้างผลงานวิจัยไปยังระบบหลังบ้านโดยไม่มี Token ยืนยันตัวตน ระบบต้องปฏิเสธคำขอด้วยรหัส `401 Unauthorized` และไม่มีข้อมูลผลงานวิจัยใหม่ถูกสร้างในฐานข้อมูล
- **TC-011 (Ref: Master TC-023 | FR-014):** การป้องกันผู้ใช้งานสิทธิ์บุคคลทั่วไป (Guest Role) ไม่ให้ส่งผลงานวิจัยเข้าสู่ระบบ (Guest Role -> HTTP 403 / Blocked)
  - *รายละเอียด:* ใช้บัญชีผู้ใช้งานที่มีสิทธิ์เป็น `guest` (นางสาวพิมพ์ชนก รัตนากร) พยายามเข้าใช้งานฟังก์ชันส่งผลงานวิจัย ระบบต้องไม่อนุญาตให้ส่งผลงานวิจัยและปฏิเสธด้วยรหัส `403 Forbidden` (หรือบล็อกการเข้าถึงหน้าส่งงานของนักศึกษา)

#### กลุ่มที่ 5: การอัปโหลดไฟล์ชนิดที่ถูกต้องและการทดสอบขนาดขอบเขต (อ้างอิง `Master TC-026` | `FR-016`)
- **TC-012 (Ref: Master TC-026 | FR-016):** การอัปโหลดไฟล์เอกสารงานวิจัย PDF ขนาดปกติ (เช่น 2.4 MB) ในขั้นตอนการส่งผลงานวิจัย
  - *รายละเอียด:* นักศึกษาล็อกอินเข้าหน้า `/student/research/new` กรอกข้อมูลงานวิจัยจนถึงขั้นตอนแนบไฟล์ เลือกไฟล์เอกสาร `งานวิจัย_ธนภัทร_ฉบับสมบูรณ์.pdf` (ขนาดปกติ 2.4 MB) ระบบยอมรับไฟล์ แสดงชื่อไฟล์และขนาดไฟล์บนหน้าจออย่างถูกต้อง
- **TC-013 (Ref: Master TC-026 | FR-016):** การอัปโหลดไฟล์เอกสารงานวิจัย PDF ขนาดพอดีขีดจำกัดสูงสุด 25 MB (Boundary Max Limit = 25 MB)
  - *รายละเอียด:* ในขั้นตอนแนบไฟล์เอกสาร เลือกไฟล์ PDF ที่มีขนาดพอดีขีดจำกัดสูงสุด 25 MB (`งานวิจัย_ธนภัทร_ขนาดสูงสุด25MB.pdf`) ระบบต้องยอมรับไฟล์ แสดงชื่อไฟล์และขนาดไฟล์ได้ตามปกติโดยไม่ขึ้นข้อความแจ้งเตือนข้อผิดพลาด
- **TC-014 (Ref: Master TC-026 | FR-016):** การปฏิเสธไฟล์เอกสารงานวิจัย PDF ขนาดเกินขีดจำกัดสูงสุด 25 MB (Boundary Over Limit เช่น 26 MB)
  - *รายละเอียด:* ในขั้นตอนแนบไฟล์เอกสาร เลือกไฟล์ PDF ที่มีขนาดเกินขีดจำกัด (`งานวิจัย_ธนภัทร_ขนาดเกินกำหนด26MB.pdf` ขนาด 26 MB) ระบบต้องปฏิเสธไฟล์ทันที แสดงข้อความแจ้งเตือนสีแดงว่า `"เอกสารต้องมีขนาดไม่เกิน 25 MB"` และไม่อนุญาตให้ดำเนินการส่งผลงาน
- **TC-015 (Ref: Master TC-026 | FR-016):** การอัปโหลดไฟล์ภาพหน้าปกงานวิจัย (PNG/JPEG/WebP) ขนาดปกติ (เช่น 1.2 MB)
  - *รายละเอียด:* ในขั้นตอนแนบไฟล์ เลือกไฟล์ภาพหน้าปก `ปกงานวิจัย_ธนภัทร_ปกติ.png` (ขนาดปกติ 1.2 MB) ระบบยอมรับไฟล์ภาพหน้าปกและแสดงผลตัวอย่างภาพหรือชื่อไฟล์อย่างถูกต้อง
- **TC-016 (Ref: Master TC-026 | FR-016):** การอัปโหลดไฟล์ภาพหน้าปกงานวิจัยขนาดพอดีขีดจำกัดสูงสุด 5 MB (Boundary Max Limit = 5 MB)
  - *รายละเอียด:* ในขั้นตอนแนบไฟล์ภาพหน้าปก เลือกไฟล์ภาพขนาดพอดีขีดจำกัดสูงสุด 5 MB (`ปกงานวิจัย_ธนภัทร_ขนาดสูงสุด5MB.png`) ระบบต้องยอมรับไฟล์ภาพหน้าปกโดยไม่แจ้งเตือนข้อผิดพลาด
- **TC-017 (Ref: Master TC-026 | FR-016):** การปฏิเสธไฟล์ภาพหน้าปกงานวิจัยขนาดเกินขีดจำกัดสูงสุด 5 MB (Boundary Over Limit เช่น 6 MB)
  - *รายละเอียด:* ในขั้นตอนแนบไฟล์ภาพหน้าปก เลือกไฟล์ภาพที่มีขนาดเกิน 5 MB (`ปกงานวิจัย_ธนภัทร_ขนาดเกินกำหนด6MB.png` ขนาด 6 MB) ระบบต้องปฏิเสธไฟล์ทันทีและแสดงข้อความแจ้งเตือนว่าขนาดไฟล์ภาพหน้าปกเกินขีดจำกัดที่กำหนด (ไม่เกิน 5 MB)

#### กลุ่มที่ 6: การตรวจสอบนามสกุลไฟล์ MIME Type และลายเซ็นไฟล์ผิดประเภท (อ้างอิง `Master TC-027` | `FR-016`)
- **TC-018 (Ref: Master TC-027 | FR-016):** การปฏิเสธไฟล์เอกสารงานวิจัยที่มีนามสกุลผิดประเภท (เช่น อัปโหลดไฟล์ `.txt` ในช่องเอกสาร PDF)
  - *รายละเอียด:* ในหน้าส่งผลงานวิจัย ขั้นตอนการแนบไฟล์ ผู้ใช้เลือกไฟล์ `บันทึกย่อ_งานวิจัย.txt` ลงในช่องอัปโหลดเอกสารวิจัย ระบบต้องปฏิเสธทันทีและแสดงข้อความแจ้งเตือน `"เอกสารต้องเป็นไฟล์ PDF"`
- **TC-019 (Ref: Master TC-027 | FR-016):** การปฏิเสธไฟล์ภาพหน้าปกงานวิจัยที่มีนามสกุลผิดประเภท (เช่น อัปโหลดไฟล์ `.txt` ในช่องภาพหน้าปก)
  - *รายละเอียด:* ในหน้าส่งผลงานวิจัย ขั้นตอนการแนบไฟล์ ผู้ใช้เลือกไฟล์ `บันทึกย่อ_งานวิจัย.txt` ลงในช่องอัปโหลดภาพหน้าปก ระบบต้องปฏิเสธทันทีและแสดงข้อความแจ้งเตือน `"ภาพหน้าปกต้องเป็น JPEG, PNG หรือ WebP"`
- **TC-020 (Ref: Master TC-027 | FR-016):** การปฏิเสธไฟล์เอกสารที่ปลอมแปลงนามสกุลเป็น `.pdf` แต่เนื้อหาภายในไม่ใช่โครงสร้าง PDF จริง (Invalid File Signature)
  - *รายละเอียด:* ผู้ใช้เลือกไฟล์ข้อความที่ถูกเปลี่ยนชื่อนามสกุลเป็น `ไฟล์ปลอมแปลงโครงสร้าง.pdf` (ไม่มี Magic Bytes `%PDF-`) เพื่อส่งเข้าสู่ระบบ ระบบตรวจสอบโครงสร้างไฟล์จริงและปฏิเสธด้วยรหัส `415 Unsupported Media Type` (หรือข้อความแจ้งเตือนข้อผิดพลาดบนหน้าเว็บ) โดยไม่บันทึกข้อมูลลงฐานข้อมูล
- **TC-021 (Ref: Master TC-027 | FR-016):** การตรวจสอบว่าไม่มีข้อมูลหรือไฟล์ภาพหน้าปกตกค้าง เมื่อแนบภาพปกถูกต้องแต่แนบไฟล์เอกสารผิดประเภท
  - *รายละเอียด:* ผู้ใช้แนบไฟล์ภาพหน้าปกที่ถูกต้อง (`ปกงานวิจัย_ธนภัทร_ปกติ.png`) คู่กับไฟล์เอกสารที่ปลอมแปลงโครงสร้าง (`ไฟล์ปลอมแปลงโครงสร้าง.pdf`) แล้วส่งข้อมูล ระบบต้องปฏิเสธการสร้างผลงาน และตรวจสอบว่าไม่มีรายการผลงานใหม่หรือไฟล์ภาพหน้าปกขยะตกค้างในระบบ

#### กลุ่มที่ 7: การควบคุมสิทธิ์การดาวน์โหลดเอกสารและกรณีผลงานไม่มีไฟล์แนบ (อ้างอิง `Master TC-035` | `FR-021`)
- **TC-022 (Ref: Master TC-035 | FR-021):** การซ่อนปุ่มดาวน์โหลดและแสดงกล่องแจ้งเตือนให้เข้าสู่ระบบ เมื่อผู้เข้าชมทั่วไป (Guest) เปิดดูหน้ารายละเอียดงานวิจัย
  - *รายละเอียด:* ผู้เข้าชมที่ยังไม่ได้ล็อกอินเปิดดูหน้ารายละเอียดผลงานวิจัย ระบบต้องไม่แสดงปุ่มดาวน์โหลดไฟล์ PDF แต่แสดงกล่องข้อความแจ้งเตือน `"Sign in to save or download this research."` เพื่อให้ผู้ใช้เข้าสู่ระบบก่อน
- **TC-023 (Ref: Master TC-035 | FR-021):** การปฏิเสธคำขอดาวน์โหลดไฟล์งานวิจัยโดยไม่เข้าสู่ระบบ และไม่เพิ่มยอดดาวน์โหลดสะสม (No Token -> HTTP 401)
  - *รายละเอียด:* เมื่อส่งคำขอดาวน์โหลดไฟล์งานวิจัยโดยไม่มี Session/Token ยืนยันตัวตน ระบบต้องปฏิเสธด้วยรหัส `401 Unauthorized` และตรวจสอบว่าตัวเลขยอดดาวน์โหลด (`download_count`) ของผลงานวิจัยชิ้นนั้นไม่เพิ่มขึ้น
- **TC-024 (Ref: Master TC-035 | FR-021):** การจัดการกรณีผู้ใช้งานที่เข้าสู่ระบบแล้วพยายามดาวน์โหลดผลงานวิจัยที่ไม่มีไฟล์เอกสารแนบในระบบ (`file_path = NULL` -> HTTP 404)
  - *รายละเอียด:* นักศึกษา (นายธนภัทร สุวรรณโชติ) ล็อกอินเข้าสู่ระบบและเปิดดูผลงานวิจัยที่ไม่มีไฟล์ PDF แนบในฐานข้อมูล เมื่อตรวจสอบสถานะบนหน้าเว็บหรือส่งคำขอดาวน์โหลด ระบบต้องแจ้งว่าไม่พบไฟล์เอกสาร (`404 Not Found`) และยอดดาวน์โหลดสะสมต้องไม่เพิ่มขึ้น

#### กลุ่มที่ 8: การบันทึกและยกเลิกรายการผลงานวิจัยที่สนใจ (อ้างอิง `Master TC-042` | `FR-027`)
- **TC-025 (Ref: Master TC-042 | FR-027):** การกดปุ่มบันทึกผลงานวิจัยเข้าสู่รายการที่สนใจ (Add Favorite) และตรวจสอบการแสดงผลในหน้า `/account/saved`
  - *รายละเอียด:* นักศึกษา (นายธนภัทร สุวรรณโชติ) ล็อกอินเข้าสู่ระบบ เปิดหน้ารายละเอียดผลงานวิจัย กดปุ่ม `"Save research"` (บันทึกผลงาน) ระบบแสดงข้อความแจ้งเตือน (Toast) ยืนยันการบันทึกสำเร็จ ปุ่มเปลี่ยนสถานะเป็นบันทึกแล้ว และเมื่อคลิกไปเปิดหน้า `/account/saved` จะเห็นการ์ดผลงานวิจัยชิ้นนั้นแสดงอยู่ในรายการผลงานที่บันทึกไว้
- **TC-026 (Ref: Master TC-042 | FR-027):** การกดปุ่มยกเลิกการบันทึกผลงานวิจัย (Remove Favorite) และตรวจสอบว่าผลงานถูกนำออกจากหน้า `/account/saved`
  - *รายละเอียด:* ต่อเนื่องจากสถานะที่บันทึกผลงานไว้แล้ว นักศึกษากดปุ่มบันทึกซ้ำเพื่อยกเลิกการบันทึก (Unfavorite) ระบบแสดงข้อความแจ้งเตือนว่านำออกจากรายการที่บันทึกแล้ว ตอบกลับด้วย HTTP 200 และเมื่อเปิดตรวจสอบที่หน้า `/account/saved` ผลงานวิจัยชิ้นนั้นจะไม่แสดงอยู่ในรายการอีกต่อไป
