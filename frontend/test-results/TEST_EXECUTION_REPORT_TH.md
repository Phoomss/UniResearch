## 4. บันทึกข้อบกพร่องและปัญหาที่ตรวจพบ (Defects & Issues)

### 4.1 DEF-FE-003: ขาดการควบคุมสิทธิ์ระดับ Edge/Middleware ในการเข้าถึงเส้นทาง `/admin`
* **ระดับความรุนแรง:** สูง (High)
* **รายละเอียด:** ไฟล์ `app/admin/layout.tsx` ตรวจสอบเพียงว่ามี Token เซสชันหรือไม่ (`hasSession()`) แต่ไม่ได้ตรวจสอบบทบาท (Role) ของผู้ใช้ และไม่มีไฟล์ `middleware.ts` ในระบบ ส่งผลให้ผู้ใช้ที่มีสิทธิ์ต่ำกว่าสามารถมองเห็นโครงสร้าง UI ของผู้ดูแลระบบได้
* **ข้อเสนอแนะในการแก้ไข:** สร้าง Next.js `middleware.ts` เพื่อดักจับและตรวจสอบสิทธิ์ตาม JWT Role ก่อนที่จะเรนเดอร์หน้าในกลุ่ม `/admin` หากไม่มีสิทธิ์ให้ส่งรหัสสถานะ 403 หรือ Redirect กลับทันที

### 4.2 DEF-FE-002: มีข้อผิดพลาดในมาตรฐานโค้ด (ESLint Errors & Warnings)
* **ระดับความรุนแรง:** ปานกลาง (Medium)
* **รายละเอียด:** จากการรัน `npm run lint` พบปัญหาทั้งหมด 37 รายการ (19 Errors, 18 Warnings) ส่วนใหญ่เกิดจากการใช้ชนิดข้อมูล `any` และการเรียกใช้ `setState` โดยตรงภายใน `useEffect`
* **ข้อเสนอแนะในการแก้ไข:** ปรับปรุงชนิดข้อมูลให้เป็นแบบ Type-safe และปรับปรุงวงจรการจัดการ State ภายในคอมโพเนนต์

### 4.3 ปัญหาด้านสภาพแวดล้อม (Environment Blocker)
* **รายละเอียด:** ระบบทดสอบขาดการจำลอง Service ฝั่ง FastAPI และ PostgreSQL ทำให้ API Endpoints หลัก (เช่น `/auth/register`, `/categories/`, `/research/`) ไม่สามารถตอบกลับได้ ส่งผลให้กรณีทดสอบที่ต้องเชื่อมต่อ API ล้มเหลวเนื่องจาก Timeout

## 5. ข้อเสนอแนะเชิงเทคนิคสำหรับการพัฒนาในก้าวถัดไป (Recommendations)

1. **(สำคัญที่สุด)** ติดตั้งและเปิดใช้งาน Backend + Database (ผ่าน Docker Compose หรือ Staging Environment) หรือตั้งค่า Mock Service Worker (MSW) เพื่อปลดบล็อกการทดสอบแบบ End-to-End
2. ติดตั้ง `middleware.ts` เพื่อป้องกันช่องโหว่การเข้าถึงแดชบอร์ดผู้ดูแลระบบ (DEF-FE-003)
3. ปรับปรุงโค้ดให้ผ่านการตรวจสอบของ ESLint เพื่อลดหนี้ทางเทคนิคก่อนการขึ้นระบบจริง (DEF-FE-002)
